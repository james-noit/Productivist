# Productivist — Agent Instructions

## Commands

```
npm install
npm run dev       # ng serve (Angular CLI dev server, http://localhost:4200)
npm run build     # ng build (production, esbuild-based application builder)
npm run watch     # ng build --watch --configuration development
npm run check:sportask # scripts/check-sportask.mjs: bundles scripts/sportask-check.ts with esbuild and runs the Sportask invariants (see **Sportask**); ~1.5 million assertions, a few seconds, no build needed
npm run check:lazy # ng build --stats-json + scripts/check-lazy-chunks.mjs: fails if a presentation (or Flow-only or Capacitor code) leaks into the initial bundle
npm run build:mobile # Android/iOS apps: environment + production,mobile build + version sync + `cap sync` (API_URL=https://<frontend-domain> to enable sync)
npm run cap:android  # cap open android (Android Studio)
npm run cap:ios      # cap open ios (Xcode, macOS only)
```

No test framework, no linter, no formatter configured (`check:sportask` is a self-check script for the pure Sportask code, not a framework).

## Thunderbird add-on

The built app also runs as a Thunderbird add-on (a WebExtension that opens `app/index.html` in a tab).

```
npm run build:tb   # production + `thunderbird` configuration, then assembles dist/thunderbird and dist/productivist.xpi
npm run tb:lint    # web-ext lint
npm run tb:run     # launches Thunderbird with the add-on loaded (needs Thunderbird installed)
```

- `extension/` holds `manifest.json` and `background.js`; `scripts/package-thunderbird.mjs` copies them next to the Angular build and syncs the manifest version with `package.json`.
- Extension pages run under a strict CSP: no inline `<script>`, no inline event handlers, no remote scripts. Keep `index.html` free of them (the theme pre-paint snippet lives in `public/theme-init.js`, the Cookie font is bundled from `src/fonts/`), and keep `inlineCritical: false` in the `thunderbird` build configuration.
- `extension/manifest.json` declares `optional_permissions` (`https://*/*`, `http://*/*`): the Git forge import asks for one origin at a time (`browser.permissions.request`, from a click) when a self-hosted forge blocks CORS.
- Manual install: Thunderbird → Tools → Developer Tools → Debug Add-ons → Load Temporary Add-on → pick `dist/thunderbird/manifest.json`.

## Mobile apps (Google Play and App Store)

The app is packaged for Android and iOS with **Capacitor 8** (`@capacitor/core`, `cli`, `android`, `ios`, plugins `app`, `local-notifications`, `splash-screen`; `@capacitor/assets` as a dev tool). Everything is on `main`, no mobile branch. The WebView serves `dist/productivist/browser` from inside the package, so the app works offline; `appId` is `com.productivist.app` (permanent once published), `appName` `Productivist`.

```
API_URL=https://<frontend-domain> npm run build:mobile   # then: npm run cap:android | npm run cap:ios
```

- **Build:** `build:mobile` mirrors `build:tb`: `scripts/write-mobile-environment.mjs` writes the git-ignored `src/environments/environment.mobile.ts` from `API_URL` (unset = sync disabled), the `mobile` configuration in `angular.json` (layered on `production`, only `fileReplacements`; critical CSS stays inlined, there is no extension CSP in a WebView) uses it, `scripts/sync-mobile-version.mjs` copies `package.json`'s version into `android/app/build.gradle` (`versionName`; `versionCode` = `major*10000 + minor*100 + patch`, 0.20.1 -> 2001) and the Xcode project (`MARKETING_VERSION`, `CURRENT_PROJECT_VERSION`, same integer; minor and patch must stay below 100), then `cap sync` copies the web build and plugins into `android/` and `ios/`.
- **Config and native projects:** `capacitor.config.ts` (appId, `webDir`, SplashScreen `launchAutoHide: false` with the light theme's background, LocalNotifications `smallIcon`/`iconColor`). `android/` and `ios/` are **committed** (they are edited by hand: icons, permissions, version); the files `cap sync` generates (`android/app/src/main/assets/public`, `capacitor.config.json`, `ios/App/App/public`, ...) are ignored by the `.gitignore`s Capacitor created, keep them. Android: `minSdk` 24, `compileSdk`/`targetSdk` 36 (from `android/variables.gradle`); `AndroidManifest.xml` removes `SCHEDULE_EXACT_ALARM` (`tools:node="remove"`) that the local-notifications plugin adds, because the end-of-session notification is inexact (`allowWhileIdle`) and needs no Play Console declaration. iOS: Swift Package Manager (no CocoaPods), deployment target 15, `ITSAppUsesNonExemptEncryption = false` in `Info.plist`, `ios/App/App/PrivacyInfo.xcprivacy` (no tracking, `UserDefaults` reason `CA92.1`; referenced from the Xcode project). Signing keystores and certificates never go in git.
- **Native code lives only in `src/core/native/`** (`native-app.ts` starts `back-button.ts` and `session-notification.ts`, hides the splash after the first paint). It is reached by one dynamic `import()` in `AppComponent`, behind `window.Capacitor?.isNativePlatform?.()` (the bridge injects that global, so detecting the platform imports nothing). **No other file may import `@capacitor/*` or `src/core/native/*`**, with exactly one more dynamic entry: `lib/forge-transport.ts` reaches `native/native-http.ts` (the Git forge import's HTTP transport) through `import()` behind the same platform check. Anything else would put Capacitor in the initial bundle; `scripts/check-lazy-chunks.mjs` (`NATIVE_ONLY`, plus a scan of every `src` file for imports of `@capacitor/` or `core/native/` outside those two entries) fails the build if it does. It observes `ClockService` from outside (`endsAt`, a read-only signal of the deadline, plus `running` and `mode`; `ClockService` imports nothing native): while a session runs it schedules one local notification at the deadline (title `chip.focusEnded`/`chip.breakEnded`, body `clock.notificationBody*`; with a Sportask session active the focus-end body also says `sportask.nextUp` "Next: <exercise>", read from `SportaskService.nextExerciseName`, which the lazy `sportask-prepare` fills during focus; a second effect reschedules when the name arrives, never asking for permission and not in the last 2.4 s; nothing of Sportask's engine or catalog is imported here), cancels it on pause/reset/mode change and ~0.8 s before the end when the app is visible (the in-app bell takes over), and asks for permission only on the first *Start* after launch, never when the app opens (a session restored at launch only schedules if already granted). **Android back button** = a synthetic `Escape` `keydown` on the focused element (or the topmost `[aria-modal]`), which everything already handles; with nothing open on `projects`/`pomodoro` it calls `App.minimizeApp()`; from `admin` it goes to `projects`.
- **Safe areas:** `viewport-fit=cover` in `index.html`; `env(safe-area-inset-*)` on the header (top), `app-root` (sides and bottom), modal overlays, drawers, the Flow focus mode and the floating pill/"+". It is 0 in a desktop browser, so the web is unchanged; any new fixed or edge-hugging element must use it too. Keep `index.html` free of inline scripts (Thunderbird CSP).
- **Backend:** the WebView origins `https://localhost` (Android) and `capacitor://localhost` (iOS) are in the default `app.cors.allowed-origins`; the Railway `CORS_ALLOWED_ORIGINS` variable replaces the default, so it must list them too (`backend/README.md`).
- **Store requirements:** `public/privacy.html` and `public/delete-account.html` (static, English and Spanish on one page, no inline scripts, the contact address is the placeholder `CONTACT_EMAIL`, to be replaced before publishing) are served by nginx at the frontend's domain (Google Play needs the delete-account URL outside the app) and copied into the app and the add-on; `account-settings` links `privacy.html` (Apple requires it for apps with accounts). Account deletion itself is `AccountService.deleteAccount`.
- **Icons and splash:** `scripts/draw-app-icon.py` (Pillow + NumPy) redraws the Thunderbird icon at 1024x1024 into `resources/` (`icon.png` opaque, `icon-foreground.png`, `icon-background.png`, `splash.png`, `splash-dark.png`); `npx @capacitor/assets generate --ios --android` turns them into the `android/` and `ios/` assets. `package.json` has an `overrides` entry pinning `sharp` to 0.34: `@capacitor/assets` pins 0.32.6, whose install script downloads a binary and which npm 12 blocks by default; 0.34 ships its binaries as optional packages and needs no script. The monochrome notification icon is `android/app/src/main/res/drawable/ic_stat_tomato.xml`.
- **Tutorials** (accounts, signing, listings, upload): `docs/mobile/` (`PLAN.md`, `google-play.md`, `app-store.md`). Gradle and Xcode builds need Android Studio / macOS; they cannot run in the Linux dev environment.

## Backend

`backend/` is a separate Spring Boot 4 / Java 21 / Postgres sync service (Maven, plain `JdbcClient`, Flyway). The Angular app stays local-first; see `backend/README.md` for run instructions and the API. It is not part of the npm scripts.

The frontend side is optional and controlled by `syncEnabled` in `src/environments/environment*.ts` (false hides the account UI and disables sync). In production the app calls `/api/*` on its own origin: the root `Dockerfile` serves the build with nginx (`deploy/nginx.conf.template`), which proxies `/api/` to the backend's private Railway address and rate-limits it, so the backend has no public domain. The Thunderbird add-on is not served from that origin, so `npm run build:tb` takes `API_URL=https://<frontend-domain>` (written to the git-ignored `environment.thunderbird.ts` by `scripts/write-thunderbird-environment.mjs`; unset means sync disabled). `AccountService` holds the email + password login/signup; the header's `login-popover` is the entry point and the account block lives in the global Configuration modal (`config-modal`: language, theme, account; `account-settings` is its account block), opened from the menu's Configuration entry or the header chip through `ViewService.openConfiguration()`; `SyncService` (instantiated in `AppComponent`) diffs the todos/projects/milestones signals against per-row metadata in `productivist.sync` to find edits and deletions, so the stores themselves know nothing about syncing — the pure logic is in `src/lib/sync-engine.ts`. Settings, daily plan and multitask state travel as one blob (`buildState`/`applyState` in `sync.service.ts`); a new persisted setting only syncs if it is added there. Device-local UI state (view, active project, filters, timer, dismissed tips) is deliberately not synced. Row hashes are taken over `toWire` output, so a codec's `toWire` must only emit an optional new field (like `Todo.status`) when it is set: an always-present key (even `null`) changes every existing row's hash, re-stamps them all as edited and re-pushes them, which can clobber unpulled edits from other devices. The other half of that rule is on the backend: an optional field the client may omit must be a wrapper type (`Boolean`, `Integer`, `Long`, …) in its `SyncDtos` record, never a primitive, because the backend uses Jackson 3, which reads an absent primitive record component as `null` and rejects the whole push (`FAIL_ON_NULL_FOR_PRIMITIVES` is on by default), as happened with `RecurrenceDto.paused`.

A signed-in user can delete their own account: `DELETE /api/account` with `{ "password" }` (`AccountController`) erases the user row, and the `ON DELETE CASCADE` foreign keys take every synced row and every session with it, so all devices are signed out. A wrong password answers **403, not 401**, because the frontend reads any 401 as an expired session and would log out silently; the admin account is refused with 409 (otherwise anyone could re-register `ADMIN_EMAIL` and inherit the role). `AccountService.deleteAccount` calls `logout()` only on success and leaves local data alone (local-first: the tasks stay on this device); the UI is the *Delete account…* button and inline `.confirm-bar` with a password field in `account-settings`, which swallows Escape through a capture listener on `document` while the question is open so the Configuration modal does not also close.

The backend also hosts the Git forge relay (`POST /api/forge/relay`, `com.productivist.forge`, see **Git forge import** and `backend/README.md`; deploy/nginx has its own `limit_req` zone for it).

The admin panel is for the one account whose email equals the backend's `ADMIN_EMAIL` (no role column; `BearerTokenFilter` grants `ROLE_ADMIN`, `SecurityConfig` guards `/api/admin/**`, see `backend/README.md`). `AccountService.isAdmin` asks `/api/admin/me`; the menu entry and the `admin` view (`AdminViewComponent` + `AdminUserModalComponent`, state in `AdminService`) exist only while it is true. The admin API returns account metadata and counts, never task or project content.

## Architecture

- **Entry:** `src/main.ts` → `src/app/app.component.ts` (`AppComponent`, standalone, bootstrapped via `bootstrapApplication`)
- **Framework:** Angular 19 (standalone components, signals) + Angular CLI (esbuild `application` builder) + TypeScript + `@ngx-translate/core`
- **Change detection:** zoneless (`provideExperimentalZonelessChangeDetection`, no zone.js polyfill). Every component is `ChangeDetectionStrategy.OnPush` and every piece of state is a signal — new components must follow both, or they will not update.
- **Lazy loading:** `app.component.html` wraps each view in `@defer (on immediate)`, so each is its own chunk. Adding a view means adding a `@defer` branch, not just an import. Three more surfaces are deferred the same way: the Eisenhower Matrix tab of `projects-view` (the `eisenhower-view`; the labels say "Eisenhower Matrix", the keys and `'matrix'` values stay), and the global Plan-my-day modal (`planning-lab-modal`, wrapping the `daily-backlog-view` wizard), which `AppComponent` renders outside the view chain whenever `ViewService.planningOpen` is true, and the Configuration modal, rendered the same way from `ViewService.configOpen`. The views are `pomodoro`, `projects` (labelled "Tasks and projects"; see **Tasks and projects page** below), `project` and `admin`. `project` is the detail view of one project (`project-detail-view`, reached by clicking a `project-card`): `ViewService.activeProjectId` and `projectPresentation` (both persisted) pick what it shows (`overview`, `kanban`, `list`, `matrix`, `roadmap`, `calendar`, `flow`; an unknown stored value falls back to `kanban`, validated in `view.service.ts`), it falls back to `projects` when the project no longer exists, and each presentation is deferred inside it, so each is its own chunk: `project-overview` (stat tiles, per-milestone progress, hand-written SVG burn-up from `lib/burnup.ts`, priority and age breakdowns), `kanban-board` (cards: `kanban-card`), `project-task-list` (sortable, inline-editable table with bulk actions) and `eisenhower-view` with its `projectId` input set (the Eisenhower Matrix, limited to the project), `project-roadmap` (milestone bars from start to due, filled by progress, expandable to dated tasks, dragging a bar shifts its dates by whole days; one computed lays everything out in pixels, `ZOOM` weeks 28 / months 8 / quarters 3 px per day) `project-calendar` (month/week grid by `dueDate`; native drag & drop onto a day plus a ⋯ date field on each chip for keyboard and touch; an Unscheduled panel for open tasks without a due date) and `project-flow` (see **Flow diagram** below). The Roadmap and the Overview's milestone rows share `milestone-dates-modal` (name, start, due; swaps a backwards range). `ViewService.showDoneTasks` (device-local, default false) hides completed tasks in Kanban, List and Calendar alike (the Done column keeps its drop target and a "N done · Show" placeholder), and `ViewService.kanbanMilestoneFilter` is the board's per-project milestone filter, shared so the Overview can open the board already filtered (`openKanbanForMilestone`). A new presentation is a `PRESENTATIONS` entry plus a `@case` in `project-detail-view`; legacy stored `planning-lab`/`eisenhower` values are migrated in `view.service.ts`.
- **Services** (`src/services/`, `@Injectable({ providedIn: 'root' })`, one per former Pinia store): `settings.service.ts` (theme, language, durations), `todos.service.ts` (todo CRUD, filters, import/export), `clock.service.ts` (timer state, bell sounds), `view.service.ts` (active view, `projectsTab`, `planningOpen`, `focusQuadrant`, clock-settings panel and `configOpen`/`configSection` state; device-local, not synced), `projects.service.ts` (project tree), `multitask.service.ts` (task drawer/multitask), `flow.service.ts` (Flow data, see below), `recurrence.service.ts` (recurring tasks, see below), `project-activity.service.ts` (device-local interaction log behind the "Recent activity" sort, see the Tasks and projects page). All persisted state uses `localStorageSignal` (`src/core/local-storage-signal.ts`) writing to `productivist.*` localStorage keys; it skips writes that would not change the stored value and coalesces bursts into one write per key per microtask.
- **Components:** `src/app/components/<kebab-name>/<kebab-name>.component.{ts,html,css}`, one directory per component, standalone, leaf-first dependency order.
- **i18n:** `@ngx-translate/core`. English is registered synchronously in `AppComponent`'s constructor via `setTranslation()`; every other locale is dynamically imported the first time it is selected. Messages in `src/i18n/locales/{en,es}.json`. Default/fallback: `en`. Use the `translate` pipe in templates (`{{ 'key' | translate }}`) or inject `TranslateService` and call `.instant(key)` for non-template usage (e.g. inside `window.confirm`).
- **Task status:** `Todo.status` (`'todo' | 'inProgress' | 'review'`, absent = todo) is the Kanban workflow column; `done` stays the single source of truth for completion and the board's Done column is derived (`columnOf` in `lib/kanban.ts`). Toggling `done` elsewhere leaves `status` alone; `TodosService.moveOnBoard` is the one place that changes both together.
- **Dates:** `Todo` and `Milestone` have optional `startDate`/`dueDate`, plain local-calendar `'YYYY-MM-DD'` strings (never `Date` or epoch ms: a due date is a day, not an instant). Parse with `parseIso` in `lib/dates.ts` (local midnight), never `new Date('2026-10-10')` (UTC); format with `Intl.DateTimeFormat(settings.language(), …)` in a `computed`, not `DatePipe` (no Angular locale data is registered). `lib/dates.ts` also has `todayIso`, `toIso`, `isIsoDate`, `addDays`, `diffDays`, `startOfWeek` (Monday), `startOfMonth`, `monthGrid`, `dueState`, `orderedDates` (swaps start > due) and `sanitizeDates`. The sync codecs emit each date only when set (like `status`) and the backend stores them as `TEXT` with a `YYYY-MM-DD` CHECK (`V4__dates.sql`). Export files are `version: 3` (2 and 3 import the same way); import runs `sanitizeDates` over todos and milestones so a hand-edited file cannot wedge sync.
- **Flow data** (the Flow view's model; the diagram is described under **Flow diagram**): a project's `Objective`s (`src/types/flow.ts`: `horizon` short/medium/long, `status` active/achieved/dropped, optional `description` and `targetDate` as 'YYYY-MM-DD', `order`) are the outcomes its work is for. They are not tasks and not the daily planner's free-text "today's objectives". A `FlowLink` is a row `{ fromKind: 'task' | 'milestone' | 'objective', fromId, toObjectiveId, projectId }` meaning "from contributes to the objective", so `Todo`/`Milestone` and their sync hashes are untouched. A `FlowLayout` is one row per project (`id` = project id) with `positions` (`${kind}:${id}` → `{x, y}`, kind `objective`, `milestone` or `nomilestone` with the project id) and `collapsed` card keys; it is its own row so dragging a node never re-stamps a task or milestone. `FlowService` (root, no dependencies, in the initial bundle, so no layout maths here) owns the three `localStorageSignal`s `productivist.objectives`, `productivist.flowLinks`, `productivist.flowLayouts`: objective CRUD (`addObjective`, `updateObjective`, `removeObjective`; a horizon change drops the objective links that stop pointing to a longer horizon), `link(from, toObjectiveId)` (returns null or the `LinkRefusal`), `unlink`, `setPosition`/`setPositions`/`clearPositions`/`setCollapsed` (call once on pointer-up), `objectivesByProject`/`linksByProject`/`layoutsByProject` maps, `exportFlow`/`importFlow`/`reset` and `sweep`. `lib/flow-rules.ts` is the pure rulebook (task/milestone → any objective of the same project; objective → only a strictly longer horizon, which rules out cycles; no duplicates) with `validateLink`, `validTargets` (for highlighting while dragging) and `isLinkCoherent`; the store enforces it, the diagram reuses it. Cascades: `ProjectsService.removeProject` → `FlowService.removeForProject`, `removeMilestone` and `TodosService.removeTodo`/`removeMany` → `removeLinksFrom`. `ProjectsService.sweepFlow()` (startup, after every sync pull, after an import) drops anything pointing at a vanished project, milestone or task (or a task that moved to another project); it lives in `ProjectsService` because `FlowService` must not inject the stores that call it. Sync codecs `objectiveCodec`, `flowLinkCodec`, `flowLayoutCodec` follow the same rule as the others (optional `description`/`targetDate` only when set; layout keys are sorted before hashing). Export files from version 4 add `objectives`, `flowLinks`, `flowLayouts` (version 5 adds `recurrences`, see **Recurring tasks**); import accepts 2 to 5 (missing arrays are empty), skips malformed rows, drops invalid `targetDate`s and links that join nothing, and Reset clears the store. Backend: `V5__flow.sql` creates `objectives`, `flow_links` and `flow_layouts` (layout positions/collapsed are JSONB, checked for shape and size in `SyncService.java`); the new push/pull lists are optional so older clients keep working.
- **Flow diagram** (the `flow` presentation): `project-flow` is the presentation root and has **one top bar with three controls**: the Diagram | Outline `.segmented` (icons `diagram` / `list`, icon-only below 600px), *Filters* (`.btn--secondary`, `filter` icon, count badge of settings that differ from the defaults, `aria-expanded`) and *Focus mode* (`.btn--ghost.btn--icon`, `maximize`/`minimize`, `aria-pressed`, key F). When something differs from the defaults a second row shows removable `.filter-chip`s ("Short term hidden ×", "Achieved hidden ×", "Dropped shown ×", "Done tasks shown ×") and *Reset filters*. Everything else lives where it is used: zoom, fit and tidy up in the canvas's controls cluster, creation in the floating "+", actions on an item in the selection toolbar, horizon visibility in the lane headers. It also owns the editors (`objective-modal`, `milestone-dates-modal`, `task-detail-modal`, `new-task-modal`, and a small New milestone `.modal-panel`) and provides `FlowViewState` (`project-flow/flow-view-state.ts`, in the component's `providers`, never root: injected by the filters drawer, the canvas and the outline). **`FlowViewState`** holds device-local, never-synced view state: `hiddenHorizons` per project (`productivist.flowHiddenHorizons`, `Record<projectId, Horizon[]>`; a hidden horizon is a collapsed lane in the diagram and is left out of the Outline: one state, two views), `showAchieved` (default on, `productivist.flowShowAchieved`), `showDropped` (default off, `productivist.flowShowDropped`), the persisted one-time `linkTipDismissed` (`productivist.flowLinkTipDismissed`), the filters-drawer open flag, and the shared `ViewService.showDoneTasks` as `showDone`; `shows(objective)` is the one filter predicate (a filtered-out objective is not rendered, nor are its links), `activeCount`/`reset()` serve the badge and the *Reset* buttons, `reveal(objective)` switches off whatever would hide a just-created objective, and it is bound to the project with `bind(() => project().id)`. **Filters drawer** (`flow-filter-drawer`, inside `side-drawer`): Horizons (three `.switch`es, the same state as the lanes), Objectives (*Show achieved*, *Show dropped*), Tasks (*Show done*), footer *Reset to defaults* and *Done*; live, no draft. **Floating "+"**: `project-flow` renders the generalised `fab-menu` with New objective (O, `target` icon, opens `objective-modal` in Short term), New milestone (M, a small name dialog) and New task (N, `new-task-modal` preset to this project with no milestone), in both modes; double-clicking an empty open horizon lane still creates an objective there. **Focus mode** (F or the top-bar button, not persisted): the presentation becomes `position: fixed; inset: 0; z-index: 25` over the app (above the page and its header, below modals and drawers), `role="dialog" aria-modal` with Tab trapped (which is also what makes `project-detail-view` not treat Escape as "back"), body scroll locked through `lib/scroll-lock.ts`, `<html>` gets `flow-focus-mode` (style.css hides the header's floating support pill), the FAB is `[contained]`, and the top bar also shows the project name; Escape leaves it only after everything inside (a question, a menu, the selection, a dialog or drawer) has used the key. `flow-canvas` is the diagram: a viewport (`touch-action: none`, `overflow: clip`, so focusing something inside can never scroll it) holding one world `div` moved with a single `translate() scale()`, the lane bands (Work | Short | Medium | Long; a horizon can be collapsed, see below), an SVG layer of links and the cards (`flow-milestone-node` for milestones and the dashed "No milestone" card whose header has no port, `flow-objective-node`). The cards are presentational; the canvas runs every gesture from `data-key` / `data-drag` / `data-port` attributes with one set of handlers on the viewport and a non-reactive `gesture` field: drag empty space or wheel to pan, Ctrl+wheel to zoom around the cursor, drag a card header to move (the live position is a local `drag` signal, committed once on pointer-up with `FlowService.setPosition`), dropping an objective in another open horizon lane changes its horizon (when that would drop objective links the card waits where it was dropped and the selection toolbar asks inline, `pending` in the canvas; a collapsed strip is not a drop target), drag from a ● port to an objective to link (`validTargets` highlights while dragging; a refused drop flashes the card and shows `flow.refusals.*`), click a link then ✕ or Delete to unlink (Delete on a selected objective opens the toolbar's inline delete question instead, never deleting straight away), drag a task row's ⠿ grip onto another card to change its milestone, `+ Add task` per card, collapse per card, double-click a card or press Enter to edit it, double-click an empty horizon lane to create an objective there; Escape answers an open question first, then clears the selection (and only then swallows the key, so a bare Escape still leaves the project, or the focus mode). **Selection toolbar** (`flow-selection-bar`, presentational): when a node is selected and no gesture is running (`busy`: drag, pan, pinch, link drag) a compact toolbar floats above it (below when there is no room), centred and clamped inside the viewport, computed in one `bar` computed from the node's world rect and the viewport so it follows pan and zoom. Objective: Edit (E/Enter), Link… (L), Mark achieved / Mark active (A), Delete (trash, Delete key: "Delete this objective? Its links are removed. [Keep] [Delete]" inline, focus on Delete); milestone card: Edit, Link…, Collapse/Expand; "No milestone" card: Collapse/Expand; task row: Open, Link…. The same inline question (`BarConfirm`) is used for the horizon change. Icon-only below 600px (aria-labels and titles stay); it carries `data-ui`, which the canvas's pointer, wheel, double-click and key handlers skip. Keyboard and touch: `L` / the Menu key / Shift+F10 (or the toolbar's Link…) open the `flow-link-menu` anchored to the toolbar (a small dialog of buttons: the objectives it may link to via `validTargets`, and its existing links, each removable; Escape closes it and is swallowed so it does not leave the project; focus goes back to the node; the Outline's rows pass `[deletable]` so their ⋯ menu also ends with *Delete objective* and the same inline question), Alt + arrows move the selected card by 8 world px (Shift: 32; an objective's Left/Right jump to the neighbouring open horizon lane, which asks the same inline question as a drag when links would break) through `commitMove`, and Alt + Left is stopped there so it does not also mean "back". - **Recurring tasks:** a `Recurrence` (`src/types/recurrence.ts`) is a *series*: a task template (title, description, importance, urgency, tags, project/milestone, pomodoros) plus a rule (`every` 1..365, `unit` day/week/month/year, `weekdays` for weekly, `mode` `schedule` or `afterCompletion`, `startDate`, optional `endDate`, `paused`, `lastDate` = the latest occurrence created). Its **occurrences** are ordinary todos with `recurrenceId` (emitted on the wire only when set), `startDate = dueDate = their date` and no `status`, so every view already understands them; a deleted series leaves a dangling `recurrenceId` that every view ignores (look the series up in `RecurrenceService.byId()`, never trust the id). All date maths is pure, in `lib/recurrence.ts` (in the initial bundle, keep it framework-free; only what creating occurrences needs lives there): `occurrenceDate`/`firstIndexAfter` (closed-form k-th date: month/year steps keep the start day clamped, 31 Jan, 28/29 Feb, 31 Mar; 29 Feb falls back to 28 Feb; weekly `weekdays` occur in every N-th week counted from `startOfWeek(startDate)`), `nextOccurrence` (the rules below), `buildOccurrence`, `occurrenceId` and `sanitizeRecurrence` (untrusted rows). **The rules:** one open occurrence per series (nothing is created while one is not done); `schedule` creates the first scheduled date after `lastDate`, but a future date just waits for its day and, if several were missed, only the *latest* one is created (no pile-ups); `afterCompletion` = the day the last occurrence was completed + `every × unit` (`startDate` for the first; `completionBase` falls back to `lastDate` when the latest occurrence was deleted); the id is deterministic, `r-<seriesId>-<YYYYMMDD>`, so two devices creating the same occurrence merge instead of duplicating; `lastDate` moves on materialize, so a deleted occurrence is never recreated; paused series and dates past `endDate` create nothing. `RecurrenceService` (root, initial bundle) holds `productivist.recurrences` (+ computed `byId`, `sorted`, `count`, `activeCount`, `occurrencesBySeries`) and the writes: `create(fields, lastDate?)`, `update(id, fields, updateOpen)`, `pause`/`resume`, `remove(id, deleteOpen)`, `clearProjectRefs`/`clearMilestoneRefs`/`sweep` (called by `ProjectsService`, which injects it; `RecurrenceService` injects `TodosService`, never the reverse: a DI cycle), `exportRecurrences`/`importRecurrences`/`reset`. Inputs: `contextTargets` (selector of the elements that have their own menu, default `[data-ctx]`; the closest match wins), `contextFallback` (default true: a press elsewhere in the host emits `target: null`; false keeps the browser's menu there) and `contextFocus` (optional selector, inside a target, of what a pointer-opened menu returns focus to; default the target itself if it is a control, else its first control). Used by `projects-view`, `plan-objectives-step` and `lot-editor`; lazy only (it is in `NEVER_INITIAL_UI`). ## Conventions

- Services expose state as `signal`/`computed`, not plain properties — always call as a function in templates/TS (`todos.filteredTodos()`, not `todos.filteredTodos`)
- All state mutations are immutable (`.set()`/`.update()` with spread/map, never mutate objects inside a signal's array in place) so change detection picks them up
- Use `inject()` for dependency injection, not constructor parameter properties
- Components use kebab-case class names with `__` modifier syntax (BEM-like): e.g., `main-view__clock`
- Todo `order` field controls display ordering; `reorderTodoBefore` recomputes order values for the affected slice
- Angular's new control-flow syntax (`@if`/`@for`/`@else if`) is used throughout instead of `*ngIf`/`*ngFor`
