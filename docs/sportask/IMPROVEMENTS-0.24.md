# Sportask 0.24: on/off switch, guided setup, coding font, editable templates

Follow-up to [`PLAN.md`](PLAN.md) (read its **Status** section and the **Sportask** bullet in `AGENTS.md` first;
every rule there still applies: zoneless + OnPush + signals, lazy chunks, `NEVER_INITIAL_UI`, terse eager strings,
optional wire fields only when set, `.confirm-bar`, `.switch`, `.btn*`, `npm run check:sportask`). Work on branch
`feature/sportask-0.24`, one phase per commit, trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`,
never push.

## Decisions

| Question | Decision |
| --- | --- |
| Where does "Sportask on/off" live? | A new synced setting `enabled: boolean` in `SportaskSettings` (travels in `settings.sportask` like the rest). A cheap eager `computed` `SportaskSettingsService.enabled` reads it from the raw signal without the sanitiser. |
| Default for existing users | Off, **except** when this device already used Sportask: stored settings with an `enrolment`, or any `sportBlocks`, or an active session → treated as on (read-time fallback when `enabled` is absent; written as `true` on the first settings write). New users start off. |
| What "off" does | Menu entry hidden; the `sportask` view falls back to `pomodoro` (validate in `view.service.ts` / the view's guard); an active session, an armed planner session and an open *Train now* block are stopped (`SportaskService.stop()`, `armed.set(null)`, `single.set(null)`); synced data is kept untouched (turning it on again shows the history). |
| Disabled entry buttons | The Pomodoro, Multitask and Plan-my-day controls stay visible but are **`aria-disabled="true"`, not `disabled`** (a disabled button gets no hover or focus, so it could not show its hint). Hover or keyboard focus shows a small non-modal popover (`role="tooltip"`, linked with `aria-describedby`): "Sportask is off. Turn it on in Configuration › Sportask." plus an *Open Configuration* link-button (`ViewService.openConfiguration('sportask')`); a click opens the same popover instead of the sheet. Escape closes it. Plan-my-day's `.switch` gets the same treatment. |
| Setup stepper | Configuration › Sportask shows, top to bottom: the **Activate Sportask** `.switch`; then, if on and setup is not done, the **stepper** in place of today's settings component; if on and done, today's settings component with a *Run setup again* button at the top; if off, a short explanation only. "Setup done" = new synced `setupDoneAt?: number` in `SportaskSettings`. Existing users that the fallback treats as on count as set up (`setupDoneAt` is backfilled the same way), so nobody who already uses Sportask is pushed through the stepper. |
| Quick vs personalised | Step 1 offers two cards. **Quick setup** shows exactly what it will set (goal *Improve mobility*, program *Desk reset*, level 1, no equipment, no constraints, rhythm *Classic 25/5*, skin *Cyberpunk*, whole-app skin on, step sounds on), the disclaimer, and *Accept and finish*. **Personalised** walks: 1 Goal (goal, program, level, or *Only free training* = no enrolment) → 2 Equipment (owned + weights/bands) → 3 Limits (no jumps, no floor) → 4 Rhythm (presets + custom) → 5 Style (skin, whole app, sounds, start without confirming) → 6 Summary + disclaimer → *Finish*. Back/Next, a step indicator ("Step 2 of 6", `aria-current="step"`), Next disabled until the step is valid, nothing is written until *Finish* (a local draft, like `task-detail-modal`), Escape inside the stepper does not close the Configuration modal while the draft is dirty (inline "Discard setup?" `.confirm-bar`). *Run setup again* opens the stepper prefilled with the current settings; *Cancel* returns to the settings without changes. |
| Reuse | The stepper reuses the existing settings blocks: extract each block of `sportask-settings` (goal, equipment, limits, rhythm, style) into small presentational components with a `value` input and a `changed` output (draft-friendly), used by both the settings page (writing through `update()`) and the stepper (writing into its draft). No duplicated forms. |
| Cyberpunk font | Replace Orbitron with **JetBrains Mono** (SIL OFL 1.1), latin 700 (and 400 only if the skin uses regular weight), copied from `@fontsource/jetbrains-mono` with `npm pack` in a scratch directory exactly like the earlier fonts (no dependency, nothing executed, `OFL-JetBrainsMono.txt` alongside). Remove the Orbitron woff2 and its licence. Display stack `'JetBrains Mono', ui-monospace, 'SF Mono', 'Cascadia Code', 'Fira Code', Menlo, Consolas, monospace`. Drop the uppercase/skew "cartoon" display treatment for titles; keep the neon palette, ink outlines and glow; numbers use `font-variant-numeric: tabular-nums`; a code-editor touch is fine (e.g. a subtle `>` prompt or `//` on section headings, purely CSS). Power yoga stays as it is. |
| Editable templates | Own templates are already editable in the panel's Templates tab. Add editing where templates are chosen: the setup sheet's free-training list gets, on each own template row, an *Edit* icon button (opens `sportask-template-editor` above the sheet, `--modal-z` higher than the sheet) and, at the end of the list, *New template*; after saving, the list reflects it and the edited/new template is selected. Built-ins keep *Duplicate* only (in the panel). Also make the Templates tab's *Edit* open without the ~1 s delay seen in the dev build if it comes from an avoidable `@defer`/lazy hop (measure first; keep it lazy if the cost is only first-load chunk fetch). |

## Phases

### Phase A: on/off switch and gating
Files: `types/sportask.ts` (`enabled?`, `setupDoneAt?`), `lib/sportask-defaults.ts`, `sanitize.ts` (+ self-check), `SportaskSettingsService` (`enabled` and `setupDone` computeds with the fallback above; keep eager cost minimal), `app-menu` (entry only when enabled), `view.service.ts`/`AppComponent` (fallback from the `sportask` view when off), stopping sessions on turn-off (lazy `session-ops`), `sportask-button` (Pomodoro + Multitask) and `plan-sportask-switch` (aria-disabled + hint popover; a small shared lazy `sportask-off-hint` component used by both), `sportask-settings` gets the *Activate Sportask* switch at the top (the stepper comes in phase B; until then "on" shows the current settings). Strings lazy in `SPORTASK_TEXTS` except anything the eager menu needs.
**Done when:** with Sportask off the menu has no entry, the three controls are visibly disabled with the hint on hover/focus/click (keyboard reachable, screen-reader described), the view falls back, sessions stop; turning it on restores everything; the fallback for existing users works (simulate: settings with an enrolment but no `enabled` → on); sync carries `enabled`; `check:sportask`, `build` (report Initial total, budget ≤ +0.3 kB), `check:lazy` pass; browser-verified at desktop and 375 px.

### Phase B: setup stepper
Files: extract the settings blocks into components (see Reuse), new lazy `sportask-setup-wizard`, `sportask-settings` composition (switch / stepper / settings + *Run setup again*), texts.
**Done when:** a fresh profile: turn on → stepper → Quick → summary → Accept → settings view with those values; again with Personalised through all six steps (Back keeps values, Next gated, nothing written before Finish, discard confirm on Escape/Cancel with a dirty draft); *Run setup again* prefilled, Cancel leaves settings unchanged; existing-user fallback skips the stepper; English and Spanish; 375 px; checks as above.

### Phase C: coding font and editable templates
Files: `src/fonts/` (add JetBrains Mono, remove Orbitron), `sportask-skin` CSS and any component CSS using the display treatment, `sportask-setup-sheet` (edit/new own templates), `sportask-templates` (latency check), docs.
**Done when:** cyberpunk surfaces render in JetBrains Mono (check `document.fonts`), no Orbitron file or reference remains (grep), `build:tb` + `tb:lint` clean, font loads only with the skin; editing and creating templates from the setup sheet works and the list/selection update; checks pass.

### Phase D: docs and version
`package.json` 0.24.0 (+ lockfile and `node scripts/sync-mobile-version.mjs` like previous bumps), AGENTS.md **Sportask** bullet updated (switch, `enabled`/`setupDoneAt`, gating, stepper, extracted blocks, font), `PLAN.md` Status gets a 0.24 subsection, final regression (`build`, `check:lazy`, `check:sportask`, `build:tb`, `tb:lint`; browser smoke test of Pomodoro/Multitask with Sportask off and on).
